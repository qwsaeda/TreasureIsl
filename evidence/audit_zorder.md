# 审计：贴图覆盖菜单文字（native RGB565 路，index 场景）

- 审计对象：`cargo run -p ti-app --features native-shell --bin treasure-native`，`QualityMode::Original`（RGB565 PCX 路），index 场景「特定区域贴图盖在菜单文字上」。
- 结论先行：**主根因 = (a) 同帧全 blit × (b) 越界裁剪策略不同，复合**：(a) 原版 `.Map` 控件经 `sub_460F8` 逐件 blit 时带 0..9 进位批计数 + 批裁剪窗（**推测**帧轮转分批），Rust `blit_scene` 把 31 件一帧全画，立绘与菜单文字同帧叠压；(b) `f1=111`（105×11 长条）x=185/191/207 越界时，原版 `sub_5E9E0`/`sub_5EAA8` 源窗求交为空 → `sub_5D9C4` 早退不画，而 Rust `blit_sprite` 的 `ox = px_x.min(FB_W-1)` 把越界精灵**拉回屏幕右缘**画 1 列宽竖条 → 越界长条残留进菜单区 = 用户报的「特定区域错位」直接来源。
- 置信度：裁剪层 (b) **高**（代码级闭合）；z-order 分批 (a) **中（推测）**（`a1[8]` 写点未定位）；文字来源「非两套」**中（推测）**。

## C. 结论

### C.7 根因判定

**主根因 = (a) 同帧全 blit × (b) 越界裁剪策略不同，复合**：

1. **z-order 层**（(a)，置信 中）：原版 `sub_460F8` 的 `a1[12]` 0..9 进位 + `a1[11]` 批号（源裁剪窗随批号增长）= **推测**帧轮转分批（每帧 ≤9-10 件，源窗空 = 不画），同帧只画 1/4 层精灵；Rust `blit_scene`（`sprite_atlas.rs:217`）31 件同帧全画，f1=115/116 立绘与 menu_shell 文字同帧叠压。
2. **裁剪层**（(b)，置信 高、可直接定位「特定区域错位」）：x=185/191/207 的 f1=111 越界精灵，原版 `sub_5EAA8` 求交为空 → `sub_5D9C4` 早退**整条不画**（A3）；Rust `blit_sprite` `ox = px_x.min(175)`（`sprite_atlas.rs:244`）→ **拉回右缘画 1 列宽竖条**（y=22 行 11px + y=44 行 11px），落在菜单区右缘 x=175 列 → **用户报的「特定区域错位」即此**。
3. **排除 (c)**：menu_shell x=56 文字与 .Map f1=115 x=115 列**不是两套文字**（B5.3，A2.3 推测：原版文字也是场景硬编码，.Map 只是右侧状态区精灵）；Rust 没有重复画两套。
4. **排除「f1=0 条」问题**：index.Map 无 f1=0（31 条全 ≥1），`blit_scene_frame` 的 f1==0 跳过不触发。
