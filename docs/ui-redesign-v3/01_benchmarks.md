# 01 · 对标游戏版面拆解

**目的**：为 v3 重设计提取**可复用的版面原则**，不是抄像素。每个游戏拆 3 块：
① 视觉重心在哪；② 信息如何分层；③ 场景间如何避免"同模板通吃"。

> 资料来源：公开截图 + 设计访谈（GDC / Dice 2018-2023）+ 个人游玩经验。引用为设计原则，
> 不抄具体数值（1080×1920 也不抄他们的横屏/竖屏比例，因平台坐标系已裁决 = 1080×1920 竖屏）。

---

## 1.1 盗贼之海 (Sea of Thieves, Rare, 2018)

### 视觉重心
**主屏 = 海 + 船 + 玩家第三人称模型**。UI 几乎不存在，只在需要时浮现：
- 血条 = 屏幕底缘 3 个小心形，仅受伤时显眼
- 弹药/物品轮盘 = 长按 Q 召出环形菜单，**圆心在屏幕中央**，松开即隐
- 地图 = 按住 E 拿出船上的实物地图物品，UI 即"角色手持的纸"

### 信息分层
1. **物理层（最强）**：船舵、帆、桅杆、地图实物——这些不是 UI，是世界里的物体
2. **浮现身（中）**：物品轮盘、对话气泡——只在交互时出现，否则隐形
3. **永久 HUD（最弱）**：血心 3 个 + 名牌，几乎透明

### 场景间不同模板
- **码头/酒馆**：第三人称角色 + 对话气泡，**无传统菜单**
- **船上**：物理交互（拉绳/转舵）+ 浮现轮盘
- **岛屿**：第一人称视角 + 物品栏角落浮现
- **地图桌**：俯视的全图视图，UI 完全消失

### 借鉴原则（v3 提取）
- **P-SoT-1 浮现式 HUD**：永久 UI 元素数量 ≤ 3 个，其余场景上下文浮现
- **P-SoT-2 视觉重心 = 游戏世界本身**，UI 不抢戏
- **P-SoT-3 场景间通过"视角/物理对象"切换，不通过"菜单列表"切换**

## 1.2 大航海时代 IV (Koei, 1997/2017 HD)

### 视觉重心
**主地图 = 等距世界地图**，港口图标是主角。UI 是**信息密集的工具盘**：
- 港口界面：左侧角色立绘 + 中间港口设施图标矩阵 + 右侧舰队状态
- 海战界面：俯视海面 + 舰队指挥菜单底部弹出（突击/炮击/撤退 4 按钮）

### 信息分层
1. **背景层**：港口全景图 / 海面 / 地图
2. **中间层**：角色立绘（左侧固定 1/4 屏宽）+ 舰队列表
3. **前景层**：菜单按钮 + 数字 HUD + 对话气泡

### 场景间不同模板
- **主地图**：俯视世界 + 小舰队图标
- **港口**：左立绘 + 中设施 + 右舰队，**三栏布局**
- **海战**：俯视海面 + 底部 4 按钮指挥盘
- **酒馆/交易所**：左立绘 + 中文字流（对话/价格表）

### 借鉴原则
- **P-UW4-1 三栏布局适用于信息密集场景**（贸易/酒馆），但不适用于游戏地图
- **P-UW4-2 左侧固定立绘锚 = 角色"在场"**，但只在该场景叙事需要时才出现
- **P-UW4-3 海战底部指挥盘 = 视觉重心在战场，按钮在边缘**，不抢占中央

## 1.3 Hades (Supergiant, 2020)

### 视觉重心
**主战斗 = 第三人称等距战斗 + Zagreus**。HUD 几乎只在角落：
- 血条 = 左下角圆环（围绕角色血量），不在屏幕顶
- Cast（远程攻击）= 角色脚下的红色印记
- Boon/Buf 图标 = 屏幕右下角小图标堆
- 死亡结算 = 中央大字"死亡"，随后数据浮现

### 信息分层
1. **角色 + 敌人层（最强）**：中央 60% 屏幕
2. **HUD 边角（弱）**：血环、Boon 图标——**不在中央**
3. **对话浮现层**：屏幕底缘 1/4 区域，对话头像左下角

### 场景间不同模板
- **战斗**：等距俯视，HUD 在角落
- **冥府大厅（房间选择）**：3 个门图标排开，UI 占屏幕中央 50%
- **神对话（Boon 选择）**：神像左 + 3 个选项中央，**强单点视觉锚**
- **死亡/结算**：中央大字 + 列表浮现

### 借鉴原则
- **P-Hades-1 HUD 边角化**：永久 HUD 不抢中央，中央留给游戏本身
- **P-Hades-2 房间选择 = 视觉中央 3 选项**，这是"分支叙事场景"的标准答案
- **P-Hades-3 死亡/结算 = 中央大字**，不是边角提示

## 1.4 八方旅人 (Octopath Traveler, Square Enix, 2018)

### 视觉重心
**主菜单 = 标题巨字 + 8 角色立绘半圆排开 + 选项小图标**。仪式感压倒功能：
- 标题"OCTOPATH TRAVELER"占屏幕上 1/3，金色发光
- 8 个角色立绘在屏幕下半圆排开
- "Continue / New Game / Load" 选项在右下角小角落

### 信息分层
1. **艺术层（最强）**：8 角色立绘 + 标题艺术
2. **选项层（弱）**：右下角小窗口
3. **次级 HUD（无）**：主菜单零 HUD

### 场景间不同模板
- **主菜单**：艺术压倒一切
- **战斗**：俯视等距 + 底部命令菜单（攻击/防御/技能/物品 4 项）
- **世界地图**：俯视像素地图 + 顶部小地图
- **村庄/对话**：横向 2.5D + 底部对话框

### 借鉴原则
- **P-OT-1 主菜单的标题艺术 ≠ 战斗的命令盘**：每个场景**视觉重心完全不同**
- **P-OT-2 主菜单选项可以很小**，因为艺术承担了 90% 视觉重量
- **P-OT-3 命令菜单 4 项是动作 RPG 战斗的黄金数**（攻击/防御/技能/物品）

## 1.5 综合原则矩阵（v3 提案基础）

| 原则 ID | 来源 | 原则 | v3 应用场景 |
|---|---|---|---|
| **P-SoT-1** | 盗贼之海 | 浮现式 HUD，永久元素 ≤ 3 | main_map / vs（减永久 HUD 数量） |
| **P-SoT-2** | 盗贼之海 | 视觉重心 = 游戏世界本身 | main_map（让棋盘占满视觉中心） |
| **P-SoT-3** | 盗贼之海 | 场景切换靠视角/对象，非菜单列表 | 全场景间过渡 |
| **P-UW4-1** | 大航海 IV | 信息密集场景用三栏 | message / saveload（左立绘+中列表+右元数据） |
| **P-UW4-2** | 大航海 IV | 左立绘 = 角色在场锚 | select_role / message |
| **P-UW4-3** | 大航海 IV | 战斗指挥盘在底部边缘 | vs（按钮往底缘放，让中央留给战斗动画区） |
| **P-Hades-1** | Hades | HUD 边角化，不抢中央 | main_map / vs |
| **P-Hades-2** | Hades | 分支选择 = 中央 3 选项 | select_role / select_map（3-5 选项居中浮现） |
| **P-Hades-3** | Hades | 死亡/结算 = 中央大字 | vs outcome |
| **P-OT-1** | 八方旅人 | 每场景视觉重心完全不同 | 全 7 场景（打破同模板） |
| **P-OT-2** | 八方旅人 | 主菜单选项可很小，艺术承担重量 | index（标题艺术 + 小选项） |
| **P-OT-3** | 八方旅人 | 战斗命令 4 项黄金数 | vs（攻击/防御/技能/物品式 4 项命令盘） |

## 1.6 当前 v2 版面对照（丑的根源诊断）

| 现状 | 违反 | v3 改向 |
|---|---|---|
| 7 场景全用"标题条+列表+提示行"三件套 | P-OT-1 | 每场景视觉重心不同 |
| index 6 项菜单 row_h=224 胖按钮填屏 | P-OT-2 | 标题艺术承担重量，选项小 |
| main_map 棋盘 y0=520 占 5% 屏 | P-SoT-2 | 棋盘是主视觉，占 ≥ 50% 屏 |
| vs 两条血条左右对称贴顶 | P-Hades-1/P-UW4-3 | 血条边角化，中央留给战斗 |
| portrait_zones 占满全屏 = 无约束 | P-SoT-1 | 改"浮现区"明确定义 |
| 场景切换无过渡 | P-SoT-3 | 加 240ms 交叉淡化 + 视角锚 |
| message 三栏未用 | P-UW4-1 | 三栏布局 + 左立绘锚 |
| select_role/select_map 列表填满 | P-Hades-2 | 3-5 选项中央浮现 |
