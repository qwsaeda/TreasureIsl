# 03 · 7 场景重设计提案（v3）

> 注：本文的「基线」记述属**历史**：像素基线机制已于 **S18.7b 退役**（三套 golden PNG + 三个 diff 测试均已删除）；
> 现行机制 = 结构不变式断言 + CPU↔Bevy 内存对拍。

**定位**：基于 `01_benchmarks.md` 提取的 12 条原则 + `02_spec_lang.md` DSL，给 7 场景
**每场景一个独立的视觉重心与情绪节奏**，打破 v2 的"7 场景同模板"。

> 每场景给：① mood + focus + rhythm（DSL 三元）；② 当前 v2 病灶；
> ③ v3 视觉重心与坐标草图（1080 空间）；④ 与 v2 的差异点。

---

## 3.0 总规则：废除"标题条+列表+提示行"三件套

v2 的 7 场景全部走这套：
```
[标题条 h=96 y=12-108]
[列表/面板 y=152-1704]
[提示行 y=1840]
```

v3 废除。每场景**必须有自己的视觉重心区**（≥ 20% 屏占比），标题与提示行是**附属元素**，
不再强制全场景出现。

| 场景 | v2 模板 | v3 mood | v3 focus.anchor | v3 rhythm.rule |
|---|---|---|---|---|
| index | 标题+菜单列表+状态 | `epic_entry` | `title_art` | `art_to_action_top_down` |
| select_role | 标题+角色列表+提示 | `hero_choice` | `portrait_carousel` | `side_anchor_center_options` |
| select_map | 标题+地图列表+提示 | `map_overview` | `map_collage` | `side_anchor_center_options` |
| main_map | 标题+HUD+棋盘+提示 | `world_explore` | `world_canvas` | `world_first_hud_corner` |
| vs | 标题+双血条+结果+提示 | `tense_battle` | `battle_arena` | `arena_center_command_edge` |
| message | 标题+正文+页码+提示 | `reading` | `text_panel` | `left_hero_right_text` |
| saveload | 标题+槽列表+提示 | `archive` | `slot_list_with_meta` | `three_column_left_hero` |

## 3.1 index（主菜单）— 仪式感入口

### v2 病灶
- 6 项菜单 row_h=224 胖按钮填屏 70%
- 标题条只占 5%，无仪式感
- 无背景艺术，靠按钮撑场面

### v3 设计

```
┌─────────────────────────────────────┐ y=0
│         (氛围天空/星空代码绘制)        │
│                                      │
│      ╔═══════════════════════╗      │ y=192
│      ║                       ║      │
│      ║   金 银 岛             ║      │ y=384   ← title_art 重心
│      ║   Treasure Isl        ║      │   display 字号 96 → v3 巨字 160
│      ║                       ║      │   （中文 96px + 英文副标 64px + 装饰线）
│      ║   ── 航海装饰线 ──     ║      │
│      ╚═══════════════════════╝      │ y=864
│                                      │
│   ▶ 新游戏    (48×48 罗盘图标)        │ y=960
│     载入游戏  (宝箱)                  │   item_h=72（v2 是 168，砍 57%）
│     读取存档  (锚)                    │
│     选项设置  (齿轮)                  │
│     帮助说明  (书)                    │
│     离开游戏  (门)                    │
│                                      │
│   build abc · modules n             │ y=1840
└─────────────────────────────────────┘
```

### scenes.json 改动

```jsonc
"index": {
  "title_art": {                                  // 新：重心锚
    "bbox": { "x": 108, "y": 192, "w": 864, "h": 672 },  // 占屏 28%（≥20% ✓）
    "display_size": 160,                          // v2: 96 → v3: 160
    "subtitle": "Treasure Isl",
    "subtitle_size": 64,
    "decoration": "compass_rose"                  // chrome 程序绘制
  },
  "menu": {                                       // 改名 list → menu（语义）
    "x": 240, "y": 960, "w": 600,                  // 居中窄列（v2: x=96 w=896 全宽）
    "item_h": 72,                                  // v2: 168 → v3: 72（瘦 57%）
    "item_count": 6,
    "icon_x_offset": -80,
    "text_x_offset": 80
  },
  "status": { "x": 540, "y": 1840 },              // 保留
  "ambient_art": {
    "type": "star_sky_code",                       // chrome 程序绘制星空
    "bbox": { "x": 0, "y": 0, "w": 1080, "h": 1920 }
  },
  "focus_anchor": { "type": "title_art", "bbox": { "x": 108, "y": 192, "w": 864, "h": 672 } }
}
```

### 关键差异
- **标题艺术承担 28% 屏**，菜单瘦到 72px 行高 = 不再"胖按钮填屏"
- **重心是 title_art 不是 menu**，违反 v2 的"标题条+列表"优先级
- **菜单不再贴边宽 896**，改窄列 600 居中，留氛围空间
- **背景是星空代码绘制**（chrome 新原语 `star_sky`），不是纯色底

### 关键差异

- **菜单从满屏列表 → 右 1/3 窄列**，重心从"列表" → "立绘"
- **菜单 item_h 从 256 → 192**（5 项 × 192 = 960，比 v2 1672 砍 43%）

## 3.10 风险与不变式

| 风险 | 缓解 |
|---|---|
| v3 改 scenes.json 破坏 v2 已 verified 的 `check_layout_doc_table_cross_check` | v3.3 试点先**双写**（v2/v3 键共存），v3.5 收口才删 v2 键 |
| chrome 新原语增加代码量 | 每个新原语 ≤ 80 行，单测覆盖 |
| 8pt 整除不再强制，可能引入 1px 抖动 | 改用 "几何容差 ≤ 2px" 断言，不强求 8 整除 |
| 死区判定算法复杂 | 用 scenes.json 矩形集合 + 简单扫描算法（Python 实现） |
| 对标游戏原则是横向借鉴，不保证竖屏适配 | v3.3 试点 index 验证后再推广，FAIL 即回滚 |

**不变式**（v3 不可违反）：
1. 每场景有且仅有 1 个 focus.anchor（占屏 ≥ 20%）
2. 永久 HUD 数量 ≤ mood 上限（P-SoT-1）
3. 死区 ≤ 15% 屏占比
4. 棋子尺寸 ≥ 瓦片尺寸（main_map player.size ≥ tile_w）
5. 命令盘元素数 ∈ {3, 4}（P-OT-3 黄金数）
