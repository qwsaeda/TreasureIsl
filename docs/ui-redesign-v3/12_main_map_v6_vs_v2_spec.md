## 1. main_map v6 设计规范

### 1.0 设计流程方法论（用户拍板，EXP-141）

> 用户 2026-10-31「你完全可以生成各种元素后去组合起来方式去生成游戏界面设计」
> = **元素级生成 + 组合合成**（本规范 §1.1~§1.5 的唯一生成路径，非整图 AI）。

- **元素级生成**：先 AI 生成各元素（羊皮底 / 铜牌×2 / 中央岛 / 海洋生物 / 舵轮 / 罗盘 / 帆船），
  元素 = 白底单主题（抠白后透明），供组合复用。
- **组合合成**：PIL 按本规范坐标/尺寸把元素组合成完整界面（可控、精确、每格差异）。
- **每格差异**：31 格每格随机**旋转（±10°）+ 缩放（±9%）** ⇒ 形状/大小/朝向略异（真不规则感），
  非规则圆/矩形/标准拼图块（用户「格式不要这么规则」；「标准拼图块」已否决）。
- **格语义**：大富翁式平面棋盘格（玩家站格），格间海水，环外海洋（EXP-141 ③）。
- 生成工具：`scripts/compose_main_map_v6.py`（幂等：`--seed` 固定则输出字节一致 + `--check` 只读）。

### 1.1 总体「古典羊皮航海图」

- **外框**：羊皮纸**做旧边框**（暖黄米色 `#d9c28a`~`#e8d9a8` + 纤维噪点 + 边缘暗角做旧 + 木框）。
  边框宽 `FRAME_W = 56px`，海洋四周留 56px 收进框内。
- **中央大海**：**蓝绿色海洋**包围岛（岛外是大海，非羊皮纸；浅海 `#4cb2a8` ~ 深海 `#185c64` +
  浪花白沫 + 礁石/沉船/波光）。海洋底 = AI 生成全景 `ocean_bg`（画质来源，非程序纯色）。
- **不规则岛 + 格子紧围岛不规则排列**（2026-10-31 用户拍板「不规则岛，格子紧围岛不规则排列」，
  **推翻**原「环形赛道 + 圆岛」）：31 格沿岛轮廓**凸包弧长等分** + 径向外推贴沿（`TILE_GAP=20px`），
  随岛形不规则排布（**非规则环**）；布局 = `scripts/compose_main_map_v6.py::tile_positions_around_island`
  （凸包 Andrew monotone chain + 弧长等分，单一事实源）→ 导出 `assets/data/main_map_v6_layout.json`，
  引擎 `render_v6_elem` 数据驱动读入（**不硬编码坐标**，§3a「精确布局 = 脚本算」）。
  参数：岛显示宽 `ISLAND_W=780px`、格显示半径 `TILE_R=36px`（径 72）、格与岛间隙 `TILE_GAP=20px`。
- **缆绳路径**：沿格子**顺序**连线（不规则前进路线，非圆环），深棕麻绳（`#4a341c` 底 + `#664828` 高光）。
- **底部**：黄铜**舵轮** CTA（`(W*0.27, H-180)` 中心，230px）+ **罗盘**装饰（`(W*0.73, H-178)`，205px）。
- **无顶部标题**（AI 概念稿误加标题，游戏不用）。
- 依据：用户「格子外面应该是大海」「总体设计」「不要标题」+「不规则岛，格子紧围岛不规则排列」。

- **可占领 / 不可占领**：
  - **可占领**（领地格）：亮铜牌 + **适中海盗骷髅**标记 + 插旗（占领后可插旗）。
    元素 = `evidence/ui_concept/main_map_v6/elements/tile_owned.png`（AI 生成，抠白）。
  - **不可占领**（功能格）：灰暗牌 + **锁链**标记（不可占领、禁止通行）。
    元素 = `evidence/ui_concept/main_map_v6/elements/tile_deny.png`（AI 生成 → `desaturate_dark` 去饱和压暗 = 灰牌）。
- **每局随机**：领地格**归属**随机分配（`rules::territory` 随机初始化，种子每局）；`--owned-ratio 0.62`
  （31 格约 19 可占领 / 12 不可占领）= **概念稿演示比例**，非游戏格型随机——格型按图固定（见 §3）。
- **形状**：木片（参考图木质圆木片：深色做旧顶 + 暖橙木侧）+ 不规则（§1.0 组合合成法：
  随机旋转/缩放 ±6% ⇒ 每格形状略异；格径 72px，相邻最小弦 ≥78px 判据 §4.2 可满足）。

## 2. VS 战斗动画 v2 设计规范（**重设计**，用户 2026-10-31 否决旧稿）

> 用户 2026-10-31「VS 战斗界面设计太烂了，对战啊，那么多游戏可以参考，你设计太烂了，反思重新设计」。
> 旧稿 `vs_anim_v2/*_concept.png` = AI 插画海报，**已否决**；本规范 = 重设计契约。

### 2.0 现状问题（对抗审计确认，重设计针对点）

- **跨帧角色不一致**：clash/duel 主角金发绿围巾无帽 ↔ result_win 黑发三角帽红头巾（不是同一人）。
- **clash 无兵对兵**：clash/duel 同构（都是主角 vs 船长对将），无方阵列队。
- **无游戏 HUD**：clash/duel 无兵力条/数字/站位（像角色封面插画，不像对战界面）。
- **背景断层**：clash/duel 羊皮海图 ↔ result_win 夕阳甲板 ↔ result_lose 雷雨大海（3 种世界）。
- **战报数值脱节**：概念稿「兵力 1200/3000」≠ 兵力模型（人手+武器，30/18 vs 20/12）。
- **无格类分层**：4 帧全是甲板对决，无攻占/副本/BOSS/遭遇差异。
- **无时间轴**：静态阶段帧，无列阵→冲锋→结算→横幅顺序。

### 2.1 参考游戏特征（构图借鉴）

- **《Fate/Grand Order》《宝可梦》回合制**：敌上/右下分层 + 顶/底状态框（1080 竖屏最贴合）。
- **《Sid Meier's Pirates!》**：敌我列阵对峙 + 底部兵力面板（水手/炮位/船员状态）。
- **《刺客信条：黑旗》海战**：目标头顶/屏幕两缘状态条 + 兵力角标 HUD。
- **《炉石 / 杀戮尖塔》**：中央战场 + 敌我双血条 + 结果横幅分层。
- **共性**：**战斗界面 = 敌我分列站位 + 顶/底双状态框（兵力条 + 数值）+ 中央战场 + 结果横幅**，
  非角色封面插画。

### 2.2 4 帧（阶段帧）

- **clash 兵对兵**：双方水手方阵列队冲锋（左下攻方 vs 右上守方对角线），突出人数/兵器对比。
- **duel 将对将**：双船长刀光冲突（左下攻方船长 vs 右上守方船长），突出上半身/脸部 + 刀光火花。
- **result_win 胜利**：狂草倾斜书法体「胜利」+ 战报兵力条 + 嘲讽文案。
- **result_lose 败北**：狂草倾斜书法体「败北」+ 战报兵力条 + 嘲讽文案。

### 2.3 人物固定统一（角色一致性方法）

- **主角**：黑色三角帽为主（头巾少量露）+ 白衬衫 + 破披风 + 弯刀 + 骷髅旗 + **少年漫大眼**
  （年轻，非海军/非成人）。
- **敌船长**：黑色三角帽 + 深色大衣 + 骷髅领巾 + 弯刀（凶悍）。
- **一致性锚定**（EXP-141 ②）：**一帧定角色**（主角/敌船长各 1 张 ref）→ 裁剪作其余帧 ref
  （图生图锚定）；ref 缩图 **≥150px**（或 JPEG 压缩 <128KB）+ 装扮词强约束（三角帽/白衬衫/破披风/少年漫大眼）。
- **校验判据**：4 帧主角身份肉眼/程序比对一致（修复「金发绿围巾→黑发三角帽」跳变）。

### 2.4 按战斗类型分层（5 类，`combat.md` §VS 界面）

| 战斗类型（格类） | VS 画面 | 主题资产 | 数据源 |
|---|---|---|---|
| **攻占战**（他人格） | 船队攻打建筑（海面舰炮 + 城墙攻城） | 地图特有建筑/城墙 | `board.json` 格类 + `territory` |
| **副本战**（无主格） | 英雄+水手登岛打守军（滩头/洞府/崖顶） | 地图特有岛屿地形 | 同上 |
| **BOSS 战**（`boss_fort`） | 英雄 vs 要塞炮台特写（巨型 BOSS） | 地图特有 BOSS 要塞 | 同上 |
| **多人同格遭遇**（后到者） | 英雄+水手对决（双方列阵，甲板/海面） | 地图特有甲板/海面 | 同上 |
| **事件**（功能格） | 不进 VS（随机事件直接结算 + 提示） | — | `rules::board` 事件 |

  VS 场景读包主题。**现状**：`21_map_package_spec.md` 尚无 `vs_theme` 字段（schema 未定）——
  本项 = 待扩展意图，落码前先补 `21_map_package_spec.md` §manifest 字段（与换图同源）。

### 2.5 兵力 HUD + 战报（数据绑定）

- **clash/duel 必带 HUD**：顶部守方框（兵力条 + 人手 N / 武器 M / 武装数）、底部攻方框（同）、中央战场。
  数据 = 运行态兵力（**目标**：`run_state`/`territory` 待接线；现原型 `vs_anim_proto.rs` 用演示常量
  攻 30 人 18 武器 vs 守 20 人 12 武器，落码时替换为运行态），**非 AI 自由数值**。
- **武装 = min(人手, 武器)**（`combat.md` §兵力模型）：HUD 显示人手/武器/武装三数，看得到「谁人多/谁有兵器」。
- **战报（result）**：战前→战后 人手/武器（武装+徒手拆分），胜败双方都损
  （`balance.combat.manpower.loss_pct` 人手 15% + `weapon_loss_pct` 武器 20%）。

### 2.6 动画时间轴（自动动效）

- **顺序**：双方列阵 → 冲锋对攻（炮火/刀光火花）→ 双方必损（人手/武器数字跳变 + 兵力条插值）→
  结果横幅（胜利/败北书法 + 战报 + 嘲讽）。全程自动，无逐回合输入（`combat.md`）。
- **交互**：跳过 / 确认 / 重打 chrome（bevy_picking `pick_key` 命中契约）。
- **判据**：时间轴可复现 + `--shot` 定格任一帧。

## 3. 业务（可占领/不可占领 + 布局 + 结算）

- **不可占领结算**：功能格事件（已有）。
