# 核心循环（Loop Core）

## 设计意图

金银岛是**回合制策略经营 + 探索冒险**。玩家扮演一名海盗船长，在等距网格地图上
往返于据点之间：**探索**发现机会，**贸易**把货物换成金币，**建造**升级城堡提升
上限与产能，**卡牌事件**带来意外（增益或损失），最终在**战斗**中挑战 BOSS。

节奏是「小步高频」：每次移动/交互 1–2 秒出结果，不做实时、不做长动画。

## 核心循环图

```
        ┌──────────────────────────────────────────┐
        │                                          │
   探索地图 ──► 遭遇据点 ──► 贸易赚金 ──► 建造升级 ──┤
   (移动)         │                                 │
        │         └──► 卡牌事件 ──┐                  │
        │                        │                  │
        └────────────────────────┴──► 战斗挑战 BOSS ─┘
```

## 目标与失败条件

| 项 | 设计 |
|---|---|
| 胜利 | 在任意地图击败该地图的 BOSS |
| 失败 | 角色 HP 归零（金币不作为失败条件，回主菜单后可再挑战） |
| 金币作用 | 支付建造/升级；不是通关门槛 |
| HP | 卡牌事件与战斗都会扣；归零即失败 |

## 回合节奏（单次玩家操作）

每个「玩家操作」= 一次移动 / 一次据点交互 / 一次战斗回合。
每次操作后按固定顺序结算：

1. **玩家动作**生效（移动一格 / 交易结算 / 攻击一回合 / 翻一张牌）；
2. **据点/地图响应**（驻留据点触发事件、移动触发随机遭遇）；
3. **状态检查**（HP≤0 → 失败；到达 BOSS → 战斗）。

## 设计约束（写进单测）

| 约束 | 断言 |
|---|---|
| 单次操作不产生多步连锁 | 一帧一次玩家操作 ⇒ 至多一次结算流水线 |
| 金币非负、≤上限 | `0 ≤ gold ≤ balance.gold_max` 恒成立 |
| HP ∈ [0, hp_max] | 扣血后不越界；归零即 `Defeat` |
| 场景无死锁 | 任意场景可经 ≤ N 次操作回到主菜单（N 取 `balance.ui.max_back_steps`） |

## 与实现的接口

表现层（`ti-app`）按 `docs/process/03_templates.md` §1 的场景模版接线；
玩法层（`ti-core/src/rules/`）提供各系统的会话对象。核心循环编排在
`ti_app::GameApp`（壳层场景状态机），`rules::main_loop::SceneStack` 仅做场景
状态码管理（`state`/`scene`/`history`，不含循环编排逻辑）。
