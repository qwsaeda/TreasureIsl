## 核心概念

### 两种输入处理模式

**事件驱动（Event-driven）—— 门铃**

```
  时间 →  0    1    2    3    4    5    6    7    8 秒
           │    │    │    │    │    │    │    │
  门铃     ·····🔔··············🔔·······
                    ↑ 有人按            ↑ 又有人按

  事件队列：  [🔔按铃@2s]  →  [🔔按铃@6s]

  优点：按了就是按了，绝不丢
  缺点：要排队（按得快的排前面）
```

**状态轮询（Polling）—— 每 5 秒看一眼门口**

```
  时间 →  0    1    2    3    4    5    6    7    8 秒
           │    │    │    │    │    │    │    │
  你在看   ●·············●·············●
           ↑ 看         ↑ 看（此时门口没人）     ↑
  有人在门口  ●─●   （来了又走了，第 6 秒已走）    第 8 秒
                    ↑
              第 4 秒有人，第 5 秒走
              但你第 5 秒才看 → 错过 ❌
```

**两者对比（同一段输入，结果不同）**：

```
  玩家在第 4 秒快速点两下（4.0s 和 4.2s），第 5 秒松开

  事件驱动：  点1 ✔  点2 ✔              两下都收到
  状态轮询：  第 5 秒只看到"还按着"      下下松开瞬间被漏掉
              → 只收到 1 次（或收到 2 次"按下"，取决于实现）
```

**怎么选**：

| 场景 | 选择 | 理由 |
|---|---|---|
| 键盘敲击、快速连点 | 事件驱动 | 不能丢 |
| 长按持续移动 | 轮询 | 就想要"现在按着没有"这个状态 |
| 触摸手势 | 事件 + 采样 | 两者都要 |

### 输入映射层

**生活类比：遥控器按键 → 电视动作**

```
  ┌─────────────────────────────────────────────┐
  │  遥控器 A（老电视）    │  遥控器 B（智能电视）  │
  ├─────────────────────────────────────────────┤
  │  [PWR]  [音量▲▼]     │  [⏻]   [vol+][vol-] │
  │                      │                     │
  └──────────┬───────────┴──────────┬──────────┘
             │                      │
             └────────┬─────────────┘
                      ▼
             ┌─────────────────┐
             │   电视的动作逻辑   │   ← 这层永远不变
             │  开机 / 音量加    │
             │  音量减 / 换台    │
             └─────────────────┘

  换遥控器 → 只改上面那层映射 → 电视逻辑一行不动
```

**游戏中：同一个动作可以绑多个按键**

```
        ┌──────────────────────────────┐
        │        逻辑动作 MoveUp         │
        └──────────────────────────────┘
             ▲          ▲          ▲
             │          │          │
        方向键↑      W 键      手机摇杆↑
        ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈
             ▲          ▲          ▲
        物理按键     物理按键     虚拟输入

  ★ 游戏逻辑只认 "MoveUp"，不关心它是 W 还是摇杆
```

**实际映射表**：

```
  物理输入            逻辑动作
  方向键↑ / W / 摇杆↑  →  MoveUp
  方向键↓ / S / 摇杆↓  →  MoveDown
  方向键← / A / 摇杆←  →  MoveLeft
  方向键→ / D / 摇杆→  →  MoveRight
  空格 / 回车 / 点击    →  Confirm
  ESC / 点击空白        →  Cancel
```

**换平台时**：

```
  PC 端               手机端
  ┌──────────┐       ┌──────────┐
  │ 方向键    │       │  虚拟摇杆  │
  │  + 空格   │       │  + 点击   │
  └────┬─────┘       └────┬─────┘
       └────────┬─────────┘
                ▼
        ┌───────────────┐
        │  MoveUp/Confirm│   ← 场景代码一行不改
        └───────────────┘
```

### 触摸与手势

**手势识别 = 看"按下-移动-释放"这条轨迹**

```
  ① 单击 Tap
     按下 ●─────────● 抬起
             短     → 选择

  ② 长按 Long Press
     按下 ●───────────────────● 抬起
             长（不移动）      → 打开菜单

  ③ 滑动 Swipe
       按下 ●
             ╲
               ╲ 快速移动
                 ● 抬起
                 → 翻页 / 滚动

  ④ 拖拽 Drag
     按下 ●
             ╲
               ╲ 慢速移动
                 ╲
                   ● 还在按住 ← 没抬起 = 拖拽
                   → 移动物体
```

**关键区别**：③ 和 ④ 都是"按下+移动"，区别在于
**移动速度**（快 = 滑动）和**有没有抬手**（没抬手 = 拖拽）。

```
  时间 ──────────────────────────────────→

  滑动：  ●────╲────╲────╲──○   抬手了
  拖拽：  ●────╲────╲────╲────╲────●  没抬手
```

## 常见坑

| 坑 | 原因 | 避免 |
|---|---|---|
| 输入丢失 | 轮询间隔太长 | 事件驱动或高频轮询 |
| 触摸坐标没转换 | 直接用物理像素 | 转换为逻辑坐标 |
| 输入处理在渲染线程 | 阻塞渲染 | 输入收集与渲染分离 |
| 没有输入缓冲 | 快速按键被忽略 | 输入队列/缓冲 |
