## 核心概念

### 帧缓冲（Framebuffer）

**生活类比：画家的画布**

```
  画布 = 176 x 220 的网格，每个格子是一个像素

    0    1    2    3   ...  175
  0 ┌────┬────┬────┬────┬────┐
    │ ░░ │ ▓▓ │ ▓▓ │ ░░ │ ░░ │  ░ = 背景色  ▓ = 已画内容
  1 ├────┼────┼────┼────┼────┤
    │ ▓▓ │ ▓▓ │ ░░ │ ░░ │ ▓▓ │  画家每涂一格 = 写一个像素值
  2 ├────┼────┼────┼────┼────┤
    │ ░░ │ ░░ │ ██ │ ██ │ ░░ │  █ = 高亮（最后涂的，压在上面）
    └────┴────┴────┴────┴────┘
   219
                     ↓
              画完 → 整张贴到屏幕（GPU 上传）
```

**本项目**：
```
  帧缓冲 = 176 x 220 的网格
  每个像素 = RGB565（16 位色，2 字节）
  总大小 = 176 × 220 × 2 = 77,440 字节（约 76 KB）
```

### 基本图元

**生活类比：画家的基本笔触**

| 图元 | 生活类比 | 用途 |
|---|---|---|
| 点 | 戳一下 | 基础 |
| 线 | 画一条线 | 边框 |
| 矩形 | 涂一个方块 | 按钮/面板 |
| 文字 | 写字 | UI 文本 |
| 精灵 | 贴一张贴纸 | 角色/地形 |

### Z-order（绘制顺序）

**生活类比：贴贴纸（后贴的盖住先贴的）**

```
  画错的顺序（先人物后背景）        画对的顺序（先背景后人物）

    ┌──────────────────┐            ┌──────────────────┐
    │  背景 背景 背景    │            │  背景 背景 背景    │
    │  背景 ▓▓▓▓ 背景    │            │  背景 人物 背景    │  ← ①先画背景
    │  背景 背景 背景    │  ← 先画人物 │  背景 ▓▓▓▓ 背景    │
    │  背景 ▓▓▓▓ 背景    │  ← ②后画背景 │  背景 背景 背景    │
    └──────────────────┘            └──────────────────┘
       人物被背景盖住 ❌               人物在背景前面 ✅
```

**正确的 5 层顺序（从底到顶）**：

```
      ┌─────────────────────────────┐  ← ⑤ 光标/高亮
      │  ┌───────────────────────┐  │  ← ④ UI 控件
      │  │  ┌─────────────────┐  │  │  ← ③ 角色/物体
      │  │  │   ┌─────────┐   │  │  │  ← ② 地形
      │  │  │   │ 背景    │   │  │  │  ← ① 背景
      │  │  │   └─────────┘   │  │  │
      │  │  └─────────────────┘  │  │
      │  └───────────────────────┘  │
      └─────────────────────────────┘

  ★ 越靠上层 = 越晚画 = 越盖得住
```

### 裁剪（Clipping）

**生活类比：画家的画框**

```
   整张世界地图 256x256

  ┌────────────────────────────────────┐
  │                                    │
  │      ┌──────────────────────┐      │  ← 画框（视野）
  │      │  ░░░░░░░░░░░░░░░░░  │      │
  │      │  ░░░░░░░░░░░░░░░░░  │      │     框内：画 ✅
  │      │  ░░░░░👤░░░░░░░░░░  │      │
  │      │  ░░░░░░░░░░░░░░░░░  │      │
  │      └──────────────────────┘      │
  │                                    │     框外：不画（浪费）❌
  │                                    │
  └────────────────────────────────────┘
```

**为什么要裁剪**：
```
  不裁剪：256×256 = 65,536 个像素全算一遍，但只有 176×220 = 38,720 个看得见
           → 白算 40%

  裁剪：  只画框内 38,720 个 → 省掉 40% 计算量
```

**本项目的做法**：
```
  绘制精灵时，检查目标矩形是否与视野矩形相交：
    相交 → 画
    不相交 → 整个跳过（连循环都不进）

  这就是 docs/process/07_render_pipeline.md 说的"越界求交裁剪"
```

### 脏行带优化（Dirty Rectangle）

**生活类比：只擦改变化的作业页**

```
  100 行的作业，第 3 行和第 50 行被改了

  全量重传：                     只传变化行：
  ┌──┬──┬──┬──┬──┬──┐        ┌──┬──┬──┬──┬──┬──┐
  │  │  │██│  │  │  │  ← 3    │  │  │██│  │  │  │
  ├──┼──┼──┼──┼──┼──┤        ├──┼──┼──┼──┼──┼──┤
  │  │  │  │  │  │  │        │  │  │  │  │  │  │
  ├──┼──┼──┼──┼──┼──┤        ├──┼──┼──┼──┼──┼──┤
  │  │  │  │  │██│  │  ← 50   │  │  │  │  │██│  │
  ├──┼──┼──┼──┼──┼──┤        ├──┼──┼──┼──┼──┼──┤
  │  │  │  │  │  │  │        │  │  │  │  │  │  │
  └──┴──┴──┴──┴──┴──┘        └──┴──┴──┴──┴──┴──┘
   100 行全传                     只传 2 行 = 省 98%
```

**时间维度看更清楚**：

```
  帧 1：画面全变  → 全量上传
        ┌──────────────┐
        │██████████████│  全部 176 行
        └──────────────┘

  帧 2：只有光标移动 → 只上传光标所在的几行
        ┌──────────────┐
        │              │
        │       ██     │  只有第 98 行附近
        │              │
        └──────────────┘

  ★ 回合制游戏里大部分帧是"什么都没变" → 能省 99% 上传量
```

**本项目**：
```
  FramePresenter 内部： dirty_rows: [bool; 220]
    每行一个标记，true = 这行改了
    present 时只把 true 的行上传到 GPU 纹理

  配合第 1 章的"按需渲染"：
    没变化 → 连 render 都不进 → dirty_rows 全 false → present 也是空操作
```

## 项目对照

### 帧缓冲

```
crates/ti-platform/src/gfx.rs — Framebuf
```

### 字形渲染

```
crates/ti-app/src/glyph_raster.rs — Raster
crates/ti-formats/src/font.rs — Font / Charset
```

本项目使用真实 `GoldLand.Fnt` 字体文件，光栅化为位图后渲染。

### 精灵渲染

```
crates/ti-app/src/sprite_atlas.rs:12 — SpriteAtlas
crates/ti-app/src/scenes/mod.rs:282   — blit_scene_sprites（SpriteHost 能力定义）
crates/ti-app/src/game_app/`（S20.0b 拆分后按模块定位）     — GameApp 侧实现/调用
```

### 帧呈现

```
crates/ti-platform/src/gfx.rs — FramePresenter
```

`FramePresenter` 负责将帧缓冲上传到 GPU 纹理，支持脏行带优化。

### 渲染路径

```
场景 render() → 帧缓冲绘制 → FramePresenter → GPU 纹理 → 屏幕
```

## 常见坑

| 坑 | 原因 | 避免 |
|---|---|---|
| 越界写入 | 没有裁剪 | 绘制前检查边界 |
| Z-order 错误 | 绘制顺序不对 | 明确分层顺序 |
| 每帧全量重绘 | 没有脏行带优化 | 只上传变化区域 |
| 文字渲染模糊 | 没有抗锯齿 | 用预光栅化字形 |
