# 第 8 章：ECS vs 组件化

## 学习目标

- [ ] 理解 ECS（Entity-Component-System）的概念
- [ ] 理解组件化（Component-based）与 ECS 的区别
- [ ] 理解为什么本项目选择组件化而非纯 ECS
- [ ] 能根据项目规模选择合适的架构

## 核心概念

### 什么是 ECS

**生活类比：乐高积木**

```
想象你在拼乐高：
  积木块 = Component（组件）
    轮子、车窗、车门、发动机...

  玩具车 = Entity（实体）
    只是一堆组件的编号，本身不含数据

  组装台 = System（系统）
    把"有轮子+有发动机"的组装成"能跑的车"
    把"有车门+有车窗"的组装成"能坐人的车"

  好处：
    想要新车？换几个组件就行，不用重新拼
```

**形式化**：
```
Entity（实体）：只是一个编号，不含数据
  0 号：[轮子, 车窗, 车门, 发动机]
  1 号：[轮子, 车窗, 飞机翼]

Component（组件）：纯数据，不含逻辑
  轮子 { 半径, 材质 }
  车窗 { 透明度, 颜色 }

System（系统）：遍历有特定组件的实体，执行逻辑
  跑动系统：遍历所有有[轮子+发动机]的实体
  载人系统：遍历所有有[车门+车窗]的实体
```

### ECS 的优势

| 优势 | 生活类比 |
|---|---|
| 组合灵活 | 想要直升机？换个螺旋桨组件就行 |
| 缓存友好 | 相同组件连续存放，CPU 缓存命中率高 |
| 并行友好 | 不同组装台可以同时工作 |

### ECS 的劣势

| 劣势 | 生活类比 |
|---|---|
| 学习曲线陡 | 要先理解"组装台"的概念 |
| 过度设计风险 | 拼一只乐高小狗也要搭组装台 |
| 调试困难 | 组件分散存放，出问题难找 |

### 组件化（Component-based）

**生活类比：拼图**

```
想象你在拼一幅画：
  整幅画 = GameObject（游戏对象）
  画上的每个部分 = Component（组件）
    背景、人物、文字...

  玩家 = 背景 + 人物 + 血条 + 名字
  敌人 = 背景 + 人物 + 血条 + 攻击力

  想要新玩家？复制一个，改几个部分就行
```

**与 ECS 的区别**：
```
ECS：组件是独立的积木，组装台负责组装
组件化：整幅画是一个整体，每个部分粘在画上
```

### ECS vs 组件化对比

| 维度 | ECS | 组件化 |
|---|---|---|
| 数据存储 | 积木分类存放（SoA） | 整幅画放在一起（AoS） |
| 逻辑位置 | 组装台（独立系统） | 画上的方法或外部 |
| 缓存友好 | 高 | 中 |
| 复杂度 | 高 | 中 |
| 适合规模 | 大（1000+ 同构实体） | 中（< 100 实体） |
| 典型项目 | 弹幕、RTS、模拟 | RPG、AVG、策略 |

### 为什么本项目选组件化

```
本项目特点：
  实体数量少（玩家 + 几个 NPC + 几个建筑）
  逻辑复杂但同质实体少
  回合制，不需要每帧更新所有实体
  需要快速开发，不是性能关键路径

结论：组件化 + 业务/渲染分离 比 纯 ECS 更合适
```

## 项目对照

### 本项目的"类 ECS"设计

```
crates/ti-core/src/domain/ — 领域模型（类似 Component）
crates/ti-core/src/rules/  — 业务规则（类似 System）
```

```
domain/
  map.rs       — 地图数据
  economy.rs   — 经济数据
  combat.rs    — 战斗数据
  selection.rs — 选择状态

rules/
  main_map.rs  — 地图规则
  battle.rs    — 战斗规则
  trade.rs     — 贸易/经济规则（注意：经济规则在 trade.rs，不叫 economy.rs）
```

### 与纯 ECS 的区别

| 纯 ECS | 本项目 |
|---|---|
| Entity = 编号 | 没有显式 Entity 编号 |
| Component = 纯数据 | Domain struct 含数据 + 简单方法 |
| System = 独立函数 | Rules 模块含业务逻辑 |
| SoA 存储 | AoS 存储（struct 字段） |

- 把 rules 逻辑改成 System 函数

思考：这个改造对本项目有什么好处？有什么坏处？

### 练习 3：选择合适架构

为以下项目选择 ECS 或组件化，并说明理由：
- 弹幕游戏（1000+ 子弹）
- RPG 游戏（10 个角色）
- 模拟城市（10000+ 建筑）

## 常见坑

| 坑 | 原因 | 避免 |
|---|---|---|
| 小项目用 ECS | 过度设计 | 根据项目规模选择 |
| 组件之间直接引用 | 紧耦合 | 通过编号或事件通信 |
| System 之间隐式依赖 | 执行顺序不确定 | 显式声明依赖 |
| 数据局部性差 | 组件分散存储 | 用 SoA 或结构体分组 |
