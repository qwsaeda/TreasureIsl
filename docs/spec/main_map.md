## §b 移动规则

### 网格取值（证据）

`sub_53808(grid_table, a, b)`（`00053808_sub_53808.c`）：

```
if (a >= grid_w || b >= grid_h) return 0;      // 越界 → 0（不可通行哨兵）
return cell_ptr[a*grid_w + b];                  // 二级指针阵列
```

`grid_table` 的 `+0/+4` = 宽/高（u32），`+8` = 行指针阵列。行指针阵列 = exe 运行期由 cell 记录构建；**oracle 层用纯函数建模：`cell(grid_w, grid_h, cell_index, a, b)` 越界返回"不可通行"**（证据：越界返回 0，`0 & 3 != 1` → 不可通行，行为等价）。

### 可通行判定（证据）

格子指针 `+22` 字节（低 2 位）`& 3 == 1` = 可通行。`sub_52080` 行 28 入口检查 `*(u8*)(a2+22) & 3 == 1` 才定位（探索格语义，推测：低 2 位 = 0 不可走 / 1 可走 / 2 据点 / 3 其他，`&3==1` 即"普通可走格"）。

### 方向枚举（证据 + 推测）

`sub_51D88`（`00051D88_sub_51D88.c`）写入 `a1+124` 的 0..=3 与 `a1+129/130` 方向位掩码（8/4/2/1）：

| 方向码（a1+124） | 探测目标格 | 语义 | 证据 |
|---|---|---|---|
| `2` | `(row+1, col)` = 南 | 行 55-58 优先级 1 | `sub_53808(…, row+1, col)+22 &3==1` → 行 55-58 |
| `3` | `(row, col+1)` = 东 | 行 47-50 优先级 2 | 行 47-50 |
| `1` | `(row, col-1)` = 西 | 行 39-42 优先级 3（方向位 4 未置时） | 行 39-42 |
| `0` | `(row-1, col)` = 北 | 行 30-33 优先级 4（兜底） | 行 30-33 |

> **推测**：东南西北的命名依据等距投影（iso_x/iso_y 公式，S1.8b）：row 增大 = iso 屏幕下移 = 南；col 增大 = iso 屏幕右移 = 东。命名不影响 oracle 差分（差分只用方向码 0..=3 的相对行为），渲染层接 S3.2 时再校准屏幕方向。

### 单步移动（oracle 化）

给定 `(grid_w, grid_h, blocked: 二维可通行表, pos)` 与方向码 `d ∈ 0..=3`：

```
Δ(row,col) = d==0 ? (-1, 0) : d==1 ? (0, -1) : d==2 ? (1, 0) : (0, 1)
new = (row+Δr, col+Δc)
合法 = 0<=new_row<grid_h && 0<=new_col<grid_w && !blocked[new]   // 越界=blocked（sub_53808 返回 0 的等价）
合法 → Some(new)，否则 None
```

（证据：`sub_53808` 越界返回 0 → `0+22` 越界读被 `&3==1` 挡住；边界内按 `+22 &3==1` 判定。）

### 走 N 步（证据）

`sub_51940(unit, n)`（`00051940_sub_51940.c`）：
- `unit+64` = row（x 坐标，`sub_52080` 行 34 写入），`unit+68` = col（行 35）；
- 每步按当前方向位 `v15`（低 3 位编码 1=西/2=南/4=东/8=北）走 1 格，`switch(v15)` case 1/2/4/8 → `--col/++row/++col/--row`（行 55-76）；
- 方向位来源：`(unit+128 当前方向掩码 & cell+23 本步可通行位 & 0xF | unit+129 目标方向位) & unit+130`，合成结果为 0 时回落本 cell `+23` 全方向重算（行 46-52）；
- 完全无方向位（`v15==0` 且回落仍 0）→ `rand() % 4` 随机选 4 方向之一再绕开已屏蔽位（行 77-94，**推测**：AI 随机漫游路径，oracle 化时该分支记为"不确定"，diff 测试固定 3 个确定性分支 + 1 个随机分支语义检查）；
- 每步经 `sub_53808` 取新格指针并 `sub_52A28` 插入 `unit+184` 轨迹链表（行 121-124）；
- 出口 `unit+128` = 本步方向位 v8（7/11/13/14 = 方向状态码，推测对应 南/西/北/东 的精灵朝向帧，行 59-71）。

> **oracle 简化**：`oracle_walk` 只确定性走"给定方向位 v15 ∈ {1,2,4,8}"的 N 步路径（每步同方向），随机分支由 diff 测试以固定 seed 的语义断言覆盖（走 1 步 + 方向位合法），不做随机序列对拍（随机序列属 S3.12 RNG 对齐范围）。

## 推测点汇总

1. 方向码 0..=3 的东南西北命名（§b）—— 由 iso 投影公式推得，渲染层校准；
2. 格子 `+22` 低 2 位的完整语义（0/1/2/3 各自含义）—— 实测仅 `&3==1` 可通行被使用，其余取值语义 **推测**；
3. 事件码 9..20 无主分派 case（§d）—— 由 `sub_29110` 排队事件消费路径处理（S3.1 域），本模块 oracle 不建模；
4. `sub_49120` 行 154 的 60% 命中分支概率（`rand()%100+1 > 40`，即 41..100 进入命中分支）—— **推测**为据点触发概率而非精确判定；
5. `sub_48654` 未命中扣减分支（行 86-91）= 资源消耗结算 —— **推测**，需 S3.6/S3.7 贸易/建造模块交叉验证；
6. 缺格 `cell(grid_w-1)` 在运行期网格中的可通行性 —— S1.8b 已证无 cell 记录，**推测** exe 构建网格时该格 = 不可通行（oracle 以 blocked=true 建模）。
